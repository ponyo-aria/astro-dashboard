## 0. Claude Code への進め方の指示（最重要）

このプロジェクトは **1ステップずつ実装 → 動作確認 → レビュー → オーナー承認 → 次のステップ** の順で進める。オーナーはプログラミング初心者なので、以下を必ず守ること。

1. **一度に1ステップだけ実装する。** 次のステップに勝手に進まない。
2. 各ステップの終わりに、必ず次の4点を報告して **止まる**。
   - 何を作ったか（専門用語を避けて2〜3行で）
   - 自動テストの結果（該当ステップのみ）
   - オーナーが手で確認する手順（番号付き、クリックや操作をそのまま書く）
   - 気になった点・判断に迷った点
3. オーナーが「OK」と言ったら、そのステップを git にコミットしてから次へ進む。コミットメッセージは日本語で「Step N: 〜」とする。
4. オーナーから修正依頼が来たら、同じステップ内で直して再度報告する。
5. 仕様に書いていないことで迷ったら、推測で進めず **質問する**。小さなことなら「〜と仮定しました」と報告に書く。
6. 「要確認」と書かれた項目は、実装前に公式ドキュメントや実際のAPI応答で確かめ、結果を報告に含める。
7. コードには日本語コメントを適度に入れる（初心者が後から読めるように）。
8. 各ステップの終わりに、本ファイル末尾の「進捗チェックリスト」を更新する。

### 各ステップ共通のセルフレビュー観点

報告前に Claude Code 自身が以下を確認すること。

- [ ] そのステップの「完了条件」をすべて満たしている

## 1. 目的

天体撮影の遠征地を決めるために、Windy・月齢カレンダー・APT DC などを行き来している手間をなくす。登録した撮影地ごとに **「どの夜に、暗くて晴れた時間が何時間あるか」** を一覧で表示する。

## 2. 前提と制約

| 項目 | 内容 |
| --- | --- |
| 利用者 | オーナー1人。Androidスマホで閲覧（PCでは見ない） |
| 形態 | PWA（ブラウザで動き、ホーム画面にアイコンを置けるWebアプリ）。サーバーは持たない |
| 公開 | GitHub Pages（無料）。※公開URLは誰でも見られるが、地点データは端末内にのみ保存し公開しない |
| 開発機 | MacBook Pro 13インチ 2020（Intel、メモリ16GB） |
| 通知 | 不要 |
| データ取得元 | Open-Meteo（非商用は無料・APIキー不要、出典表示が必要） |

## 3. 技術構成（推奨）

| 役割 | 採用 | 理由 |
| --- | --- | --- |
| ビルド | Vite | 軽量で設定が少ない |
| 言語 | JavaScript（フレームワークなし） | 初心者が読みやすい。必要ならTypeScriptに変更してよいが、その場合はStep 0で相談すること |
| 天文計算 | astronomy-engine（npm） | 薄明・月の出入り・月高度を端末内で正確に計算できる |
| グラフ | Chart.js、または手書きSVG | 時間別の雲量グラフ用。Step 6で選定し理由を報告 |
| テスト | Vitest | 判定ロジックと天文計算の自動テスト |
| 保存 | localStorage（地点データ）、Cache API / IndexedDB（予報キャッシュ） | サーバー不要 |
| オフライン | Service Worker（vite-plugin-pwa など） | 圏外でも最後の予報を表示 |

フォルダ構成は Step 0 で提案し、オーナーの承認を得てから作ること。判定ロジック・天文計算・API取得は画面から分離し、単体テストできる形にする。

## 4. 用語と定義

| 用語 | 定義 |
| --- | --- |
| 夜（D日の夜） | D日の日没から D+1日の日の出まで。例：「11/8の夜」＝11/8夕方〜11/9朝 |
| 暗い時間 | 太陽高度が −18°以下（天文薄明の終了〜開始）**かつ** 月が地平線下（月高度 0°未満） |
| 晴れ | その時刻の低層・中層・高層雲量が **すべて 20%以下**（薄雲も不可のため全層で判定） |
| 撮影可能時間 | 暗い時間のうち、晴れが **連続している** 最長の長さ（時間） |
| 撮影可 | 撮影可能時間が **3時間以上** |
| 周辺点 | 地点から北・東・南・西へ約5km離れた4点 |
| 低層雲リスク | 暗い時間帯に、周辺点のどこかで低層雲が 30%を超える |

しきい値（20%、30%、3時間、5km）は後で調整するので、**1か所の設定ファイルにまとめる**こと。

## 5. 機能仕様

### 5.1 地点管理

- 地点の追加・編集・削除・並べ替え
- 項目：名前、緯度、経度、標高（自動取得、手で修正可）
- 入力方法：
  - 「35.42, 138.58」形式の座標の貼り付け
  - Googleマップの長いURL（`@緯度,経度` を含むもの）の貼り付け
  - 短縮URL（`maps.app.goo.gl/...`）はブラウザから展開できない可能性が高い。**要確認**。無理なら「座標をコピーして貼ってください」と案内表示する
- 標高は Open-Meteo Elevation API で取得（**要確認**：エンドポイントと応答形式）
- 初期地点（初回起動時のみ登録）：

| 名前 | 緯度 | 経度 | 備考 |
| --- | --- | --- | --- |
| 朝霧高原 | 35.42（仮） | 138.58（仮） | 正確な座標は Step 1 でオーナーに確認 |
| 八ヶ岳ふれあい公園 | （未定） | （未定） | Step 1 でオーナーに確認 |
| 天城高原ハイカー駐車場 | （未定） | （未定） | Step 1 でオーナーに確認 |

- 書き出し・読み込み（バックアップ）：地点リストをJSONファイルとしてダウンロード／ファイルから読み込み。読み込み時は「置き換え」か「追加」を選べるようにする
- 将来の拡張用に、地点データに「標高」を必ず保持する（雲海判定で使う予定。MVPでは判定に使わない）

### 5.2 予報データ取得

取得するモデルと範囲：

| モデル | 用途 | 範囲 |
| --- | --- | --- |
| 気象庁 MSM | 3日前〜当日の詳細判断、◎判定 | 約4日先まで |
| ECMWF IFS | 1週間前の見込み判断 | 7夜分 |

取得する項目（1時間ごと）：

- 雲量：低層・中層・高層（`cloud_cover_low` / `cloud_cover_mid` / `cloud_cover_high`）
- 降水量（前日〜当日の合計を出すため、過去1日分も取得）
- 気温、露点温度
- 地上の風速・最大瞬間風速
- 上空約1.5km（850hPa）の風向き・風速（雲が流れてくる方向の矢印用）

**要確認**（Step 3の最初に実際のAPI応答で確かめ、結果を報告）：

1. 各モデルのモデル名パラメータ（例：MSMは `jma_msm`、ECMWFは `ecmwf_ifs` など）
2. MSMで850hPaの風が取れるか（取れなければECMWFの850hPaで代用し、報告）
3. 複数地点を1回のリクエストで取得できるか（できれば地点数×5点の通信回数を減らす）
4. 各モデルの「最終更新時刻（初期時刻）」の取得方法（Open-Meteo の Model Updates 情報など）
5. 非商用無料枠の利用制限（1日あたりのリクエスト上限）に収まるか

取得タイミング：アプリを開いた時と、更新ボタンを押した時。前回取得から10分以内なら再取得しない（無駄な通信を避ける）。

### 5.3 判定ロジック

夜ごと・地点ごと・モデルごとに以下を計算する。

1. その夜の「暗い時間」を天文計算で求める（5〜10分刻みで計算してよい）
2. 1時間ごとの予報で各時刻が「晴れ」か判定する
3. 暗い時間と晴れが重なる連続時間の最長を「撮影可能時間」とする
4. 3時間以上なら「撮影可」
5. 周辺点4か所の低層雲を見て「低層雲リスク」を判定する

表示する総合判定：

| 表示 | 条件 |
| --- | --- |
| ◎ 可 | MSMの範囲内の夜で、MSMとECMWFがどちらも「撮影可」 |
| △ 割れ | MSMの範囲内の夜で、2モデルの判定が食い違う |
| × 不可 | MSMの範囲内の夜で、どちらも「撮影不可」 |
| 参考 | MSMの範囲外（5〜7夜目）。ECMWFの判定のみを「参考：可／不可」と表示し、◎は出さない |
| ⚠ 低層雲リスク | 上記に重ねて表示する警告。判定そのものは変えない |
| 暗い時間なし | 月や季節により暗い時間がそもそも3時間未満の夜は「月明かりで不可」など理由が分かる表示にする |

**判定ロジックは自動テストを必ず書く。** 最低限、次のケースを含めること。

- 全層20%以下が4時間続く → 撮影可
- 晴れが2時間＋曇り1時間＋晴れ2時間 → 連続最長2時間で不可
- 中層雲だけ40% → 晴れではない
- 暗い時間が2時間しかない夜 → 雲がなくても不可
- 日付をまたぐ夜（23時〜翌3時が晴れ）→ 正しく1つの夜として数える
- MSMのデータが途中で切れている夜 → 「参考」扱い

### 5.4 画面

#### (1) トップ画面

- 登録地点ごとに、今後7夜分のカードを横並び（横スクロール）または表で表示
- 各カード：日付（曜日付き）、総合判定（◎△×参考）、撮影可能時間（例：4.5h）、⚠表示
- 画面上部：最終取得時刻、各モデルの最終更新時刻、更新ボタン
- 圏外・取得失敗時：保存済みの予報を表示し、「○時○分時点のデータ（オフライン）」と明示

#### (2) 地点詳細画面（カードをタップで開く）

- 夜間（日没〜日の出）の時間別グラフ：
  - 低層・中層・高層雲量（3本の線または積まない棒）
  - 暗い時間帯を背景の帯で表示
  - 月高度（別軸または小さな線）
  - 晴れのしきい値20%の補助線
- 数値情報：
  - 前日〜当日の降水量合計（地面のぬかるみ判断用）
  - 夜間の最低気温
  - 結露リスク：気温と露点の差。初期値は「2℃以下で高」「4℃以下で注意」（設定ファイルで調整可）
  - 風速・最大瞬間風速。初期値は「5m/s以上で注意」（設定ファイルで調整可）
  - 雲が流れてくる方向の矢印（850hPaの風向き。**参考情報で判定には使わない**と画面に明記）
- 周辺点4か所の低層雲の状況（どの方角で雲が多いか）
- モデル切り替え（MSM / ECMWF）

#### (3) モデル比較

- 地点ごとに、夜×モデルの判定を表で並べる
- 各モデルの最終更新時刻を表示し、「次の更新は○時ごろ」の目安が出せれば出す（**要確認**：可能か）

#### (4) 地点管理画面

- 5.1 の機能

#### (5) ランチャー

- ボタンで以下を開く：Windy、SCW、Polaris Scope、SkySafari 7 Plus、AstroBin
- Windy・SCW・AstroBin はWebのURLで開く（Windyは地点の座標を渡せるか**要確認**）
- Polaris Scope・SkySafari はAndroidアプリの起動を試みる（`intent://` 形式のリンク。**要確認**：各アプリのパッケージ名）。起動できない場合はPlayストアのページを開く
- 実機で1つずつ動作確認する

#### (6) 出典表示

- 画面下部またはメニューに「気象データ：Open-Meteo.com（CC BY 4.0）」とリンクを表示する

### 5.5 オフライン対応

- アプリ本体（HTML・JS・CSS）をService Workerでキャッシュし、圏外でも起動できる
- 最後に取得した予報データを端末に保存し、圏外でも表示する
- 天文計算は端末内で行うため、圏外でも暗い時間は表示できる

### 5.6 MVPで作らないもの

予報変化の通知、SCWのデータ取得、AstroBin連携、機材台帳との統合、標高を使った雲海判定、地点メモ、出発目安時刻、月齢の許容設定、路面凍結の注意、答え合わせ・精度評価（別途PCの検証プログラムで実施）

## 6. 実装ステップ

各ステップの「確認」は、Claude Code の自動テスト・セルフチェックと、オーナーの手動確認の両方を行う。

### Step 0：開発環境と土台づくり

- 作るもの：Viteのプロジェクト、フォルダ構成、「Hello」だけ表示する画面、Vitestの雛形、GitHubリポジトリ、GitHub Pagesへの公開
- Claude Code の注意：
  - オーナーはGitHub初心者。リポジトリ作成やPagesの設定でオーナーが画面操作する箇所は、手順を1つずつ説明する
  - GitHub Pagesへの公開方法は、まず一番簡単な方法を提案し、オーナーと相談して決める（GitHub Actions を使う方法は学習も兼ねるので、使う場合は仕組みを簡単に説明する）
- 完了条件：
  - Macのブラウザで `npm run dev` の画面が見える
  - スマホのブラウザでGitHub PagesのURLを開いて「Hello」が見える
  - `npm test` が通る（ダミーテスト1件）
- オーナーの確認：スマホで公開URLを開く

### Step 1：地点管理

- 作るもの：地点の追加・編集・削除・並べ替え、座標の貼り付け入力、標高の自動取得、端末への保存、JSONの書き出し・読み込み、初期地点3か所
- 最初にやること：初期3地点の正確な座標をオーナーに確認する
- 完了条件：
  - 地点を追加して再読み込みしても残っている
  - 書き出したJSONを削除後に読み込むと元に戻る
  - 不正な座標（文字や範囲外）を入れるとエラーメッセージが出る
- オーナーの確認：スマホで地点を1つ追加・削除し、書き出し・読み込みを試す

### Step 2：天文計算

- 作るもの：夜の範囲、天文薄明の終了・開始、月の出・月の入り、月齢、月高度、「暗い時間」の計算
- 自動テスト：特定の日付・地点で、計算結果が既知の値（国立天文台の暦計算室などの値）と数分以内で一致すること
- 完了条件：画面に各地点・今後7夜の「暗い時間」が一覧で出る（判定はまだ不要）
- オーナーの確認：同じ日を APT DC と月齢カレンダーで見て、薄明と月の時刻が大きくずれていないか比べる

### Step 3：予報データの取得

- 最初にやること：5.2 の「要確認」5項目を実際に調べて報告する。結果によって仕様変更が必要なら、オーナーに相談する
- 作るもの：MSMとECMWFの取得、周辺点4か所の取得、最終更新時刻の取得、通信失敗時の処理、取得データのキャッシュ
- 完了条件：
  - 各地点・各モデルの時間別の雲量が取得でき、確認用の簡易表に表示される
  - 機内モードで開くとエラーで止まらず「取得できませんでした」と出る
- オーナーの確認：Windyで同じ地点・同じ時刻のECMWFの雲量を見て、大きくずれていないか比べる

### Step 4：判定ロジック

- 作るもの：5.3 の判定（撮影可能時間、撮影可、総合判定、低層雲リスク）。しきい値は設定ファイルに集約
- 自動テスト：5.3 に列挙したケースをすべて含める
- 完了条件：テストがすべて通り、確認用の簡易表に判定が出る
- オーナーの確認：直近の夜について、判定が自分の感覚と合っているかを見る

### Step 5：トップ画面

- 作るもの：5.4(1) のカード一覧、最終取得時刻、モデル更新時刻、更新ボタン
- 完了条件：スマホで3地点×7夜が見やすく表示され、片手で横スクロールできる
- オーナーの確認：スマホで操作して、見やすさ・分かりやすさの感想を伝える（ここでデザインの修正を受け付ける）

### Step 6：地点詳細画面

- 作るもの：5.4(2) のグラフと数値情報、周辺点の状況、風向きの矢印、モデル切り替え
- 最初にやること：グラフの描き方（Chart.js か手書きSVGか）を理由付きで提案する
- 完了条件：カードをタップすると詳細が開き、戻るとトップに戻る
- オーナーの確認：グラフの見やすさ、結露・風の表示が判断に使えるか

### Step 7：モデル比較画面

- 作るもの：5.4(3)
- 完了条件：夜×モデルの判定が並び、更新時刻が分かる
- オーナーの確認：Windy（ECMWF）とSCWで普段食い違う夜に、比較表が判断の助けになるか

### Step 8：オフライン対応・PWA化

- 作るもの：Service Worker、アプリのアイコン、ホーム画面への追加、予報データのオフライン表示
- Claude Code の注意：Service Worker はHTTPSでないと動かないため、スマホでの確認はGitHub Pagesに公開してから行う
- 完了条件：
  - スマホのホーム画面にアイコンを追加できる
  - 一度開いた後、機内モードでも起動し、最後の予報が「オフライン」表示付きで見える
- オーナーの確認：機内モードで起動してみる

### Step 9：ランチャー

- 作るもの：5.4(5)
- 最初にやること：各アプリのパッケージ名と、`intent://` で起動できるかを調べて報告
- 完了条件：各ボタンが実機で意図どおり動く（動かないものはPlayストアへ誘導）
- オーナーの確認：スマホで全ボタンを1つずつ押す

### Step 10：仕上げと総合テスト

- 作るもの：出典表示、エラー表示の見直し、READMEの作成（使い方、しきい値の変え方、データのバックアップ方法）
- 総合テスト（オーナー）：
  1. 実際に遠征を検討する週に、1週間前・3日前・前日にアプリだけで判断してみる
  2. 判断が Windy・月齢カレンダー・APT DC を見た場合と大きく食い違わないか確認する
  3. 気になった点をまとめて Claude Code に伝える
- 完了条件：オーナーが「これで遠征地を決められる」と判断する
